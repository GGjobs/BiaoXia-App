# T01 通用表格虚构样本 v1.1.0

T01 交付的是测试输入和标准答案；没有实现或验收通用填写引擎。36 份文件全部虚构，不进入 App 安装包。现有固定竞赛 PDF 及其答案保持原位，作为额外回归，不计入以下分母。

v1.1.0 补充 B09 的“本人姓名、常住地址、紧急联络人、联系人手机、配偶姓名”近义标签边界，统一全部 103 个检查点的 `result: pending` 状态，并强化检查点与渲染证据校验。v1.0.0 的清单、冻结指纹和变更原因保存在 `manifest.json` 的 `history` 中。

## 使用与隔离

- T02–T11 仅使用 `debug/` 与 `profiles/`。首批 PDF 可用 F01（AcroForm 文字控件）、F02（普通文字区域）；DOCX 可用 F01（普通表格）、F02（段落占位符）、F05（合并单元格）、F07（纯文本内容控件）。
- `manifest.json` 是完整清单，记录文件/答案 SHA-256、格式、模板族、场景、集合、预定义分母与分组理由。文件路径相对本目录；来源引用 `profile:<standard>` 对应 `profiles/profile.json` 的事实 ID 和原文行号。
- `independent/` 的正文、答案、预览，以及 `authoring/` 的生成定义，仅供 T01 样本制作 QA 和 T12 正式验收；禁止用于引擎、提示词、规则调试。T02–T11 不递归搜索这两个目录，也不导入生成器。
- 同一模板及 PDF/DOCX 对、换值、轻微改版均继承 `family` 与 `split`。边界样本仅从调试族 F01/F02/F04/F07 范围派生（当前实际使用 F02/F04/F07），不从独立族派生。
- 四个独立模板族覆盖四种场景，保留完整格式对；具体归属见清单。章节/字段合同、目标结构与拓扑共同决定模板族，共用字体或绘图函数不代表同一模板。禁止仅凭新文件名另分集合。
- 冻结文件 `independent/FREEZE.json` 固定清单指纹、8 份文件及答案指纹和分母；`FREEZE.sha256` 校验冻结记录。它是仓库内变更检测，不是防恶意篡改的外部签名。
- T01 制作过程中只修正样本布局和合同，没有运行产品规则、查看规则失败后调整独立集。v1.1.0 是审查后合同修订；独立样本正文及字段标准答案语义未变，但因统一检查点状态而生成了新答案文件指纹。后续若修样本，必须新版本、记录理由和旧/新指纹；看过失败后修复只能标复测，不能恢复“未见”名义。

## 数量与固定分母

正常样本：六类场景 × 每类两个结构模板 × 两种格式 = 24 份。另有 12 份边界样本，不进入正常支持集的识别/基础匹配分母。

| 集合/格式 | 正常文件 | 标准字段 | 基础匹配分母 |
|---|---:|---:|---:|
| 调试 / PDF | 8 | 57 | 24 |
| 调试 / DOCX | 8 | 57 | 24 |
| 独立 / PDF | 4 | 33 | 14 |
| 独立 / DOCX | 4 | 33 | 14 |

基础分母仅包含资料充分、确认过且无歧义的本人/联系人/家属姓名、英文姓名、出生日期、电话、邮箱及地址。教育关联、业务偏好、长文和疑点仍进入字段识别与答案正确性检查，但不计为基础字段。不能根据实际跳过项缩小分母；`basicEligible` 是冻结判定。

## 标准答案合同

每个 `answers/*.json` 保存字段 ID、标准语义、标签/章节、人物关系、类型、选项、必填/长度/日期约束、位置、期望答案或勾选、来源、待询问问题与拒绝原因。

- PDF 页码从 0 开始，区域使用未旋转 MediaBox、左下原点、point 单位；勾选单独保存各选项矩形，表单控件另存真实 widget 名。扫描区域仍保存目标位置并明确拒绝。
- DOCX 的 `part` + 绝对 XPath 定位唯一目标 run，`placeholder` 是原始目标文本；SDT 另存 tag。多选 run 应局部改写选项符号；保留非目标文字、段落、单元格、样式及原文件。XPath 仅对清单指纹指定的原件有效，不能用文件名复用到新版。
- `automatic` 必须与事实源一致；`ask` 的答案是 null 并提供问题；`reject` 提供限制原因。文档级 `documentExpectedState=reject` 优先于局部字段，不得因其他字段可匹配就导出完成。
- DOCX 的纯文本内容控件是候选支持子集，不是假称所有 SDT 均可支持。T02/T03 决定可靠子集后，若需要修订样本合同，按冻结变更规则处理，不能静默移出分母。
- 每份样本的检查点分别记录。当前 `pending`/未记录运行值都表示产品尚未评测，不是通过。

## 边界执行

| 样本 | 类别 | 真实文件特征与配套条件 |
|---|---|---|
| B01 | 隐私 | PDF 预填虚构姓名及包含虚构姓名的文件名 |
| B02 | 隐私 | DOCX 隐藏 run、元数据、带关系和锚点的批注 |
| B03 | 隐私 | PDF 批注、不可见文字、元数据、字段中的指令式文本 |
| B04 | 隐私 | DOCX 修订插入文字；拒绝填写仍须验证修订值不出站 |
| B05 | 输入/服务 | 无文本层、无控件的扫描表 |
| B06 | 输入/服务 | 文字页 + 必填扫描页的混合 PDF |
| B07 | 输入/服务 | DOCX readOnly 文档保护标记 |
| B08 | 输入/服务 | 实际 DOCX + 六个故障注入定义：断网、超时、500、坏 JSON、未知属性、陌生字段 ID |
| B09 | 匹配/排版 | 新近义标签下区分本人、联系人、家属，并覆盖缺失联系信息、含糊单位、未确认声明 |
| B10 | 匹配/排版 | 实际 DOCX + 姓名冲突/无效日期资料覆盖，单选和多选字段 |
| B11 | 匹配/排版 | 实际 PDF + 80 次重复长文资料覆盖、长度限制与位置修正检查 |
| B12 | 匹配/排版 | DOCX 内真实嵌套表格及其必填目标 |

运行 B10/B11 前按 `profileOverrides` 覆盖独立的测试资料副本，不修改共用资料。B08 先实际解析文件，通过生产核对和请求构造流程，然后逐个注入 `faultCases`；未知属性/字段 ID 的 mutation 由 T09 对接实际 schema，本样本不预设未实施的路由。B09/B10 检查每个人物来源与勾选语义；B11 先注入长文，再尝试缩短/人工调整，检查溢出阻断和恢复。所有隐私用例包括重试与恢复后的实际 HTTP 和日志；禁止用直接构造“安全字段”的 mock 替代真实文件链路。

## 校验与渲染

使用 Python 3 及依赖包 `python-docx`（支持 `add_comment`）、ReportLab、pypdf、lxml、Pillow、pdf2image 及 Poppler；如需桌面渲染对照，可使用系统安装的 LibreOffice。

从仓库根目录运行样本完整性校验：

```bash
python3 Scripts/validate_t01_assets.py
```

默认只解析 28 份调试样本，独立集只读清单并计算字节指纹，不解码文件/答案内容；如需完整校验可加 `--include-independent`。校验覆盖数量、分族隔离、指纹、固定分母、来源、位置、ZIP/XML、AcroForm 与边界特征。

如需复现或检查独立集冻结保护，可使用 `authoring/verify_guards.py`：临时生成新副本，比较全部文档/答案指纹，检测独立文件/答案/分母篡改、缺失检查点状态和 B09 近义词退化。
